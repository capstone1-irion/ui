# 균형형 워크스페이스·JSONL 가져오기 검증

2026-10-12 KST · 기존 v0.2 기능을 유지한 v0.3 화면 및 연결 복구 변경입니다.

- 입력 참조·비행·epoch·대상·근거 구간이 같은 두 판정에만 일치/불일치 요약 표시. 점수를 평균하거나 건강도로 변환하지 않음.
- 모델 카드에서 판정 근거로 이동. 각 API 설정 및 실시간 연결 모달 유지.

- 마지막 선택 비행을 같은 브라우저에 저장하고 새로고침 후 유지.

## 업로드 오류 원인과 복구

확인 당시 `127.0.0.1:8765/api/health`는 `Connection refused`였습니다. 기존 사용자 탭에는 서버가 종료된 후 남아 있는 v0.2 화면과 `Failed to fetch`가 표시되어 있었습니다. 이전 검증 서버가 종료된 상태였으며, 첨부 파일의 파싱 실패와 구분됩니다.

첨부 원본은 3,588,530 bytes, SHA-256 `487299172cb2d519d062565f0ab0117ca5952d4e51b3b86a897ae4519309932e`입니다. 독립 API 검사와 **실제 브라우저의 비행 로그 가져오기 버튼** 모두 성공했습니다. 4281건 사용 / 4282건 전체 / 321번째 행 1건 제외를 확인했습니다. 원본은 변경하지 않았습니다.

`server.sh start|status|stop`을 추가했습니다. start는 로컬 서버를 백그라운드로 유지하며 로그인 자동 실행이나 외부 공개를 설정하지 않습니다. stop은 기록된 서버 인스턴스가 현재 응답하는 서버와 일치하는 경우에만 종료합니다. 기존 `start.sh` 전경 실행도 유지합니다.

브라우저는 서버 상태를 확인하고 네트워크 오류를 한국어 연결 안내로 표시합니다. 서버의 422·413·500 등 HTTP 오류와 JSON 응답 오류를 별도로 처리합니다. POST 자동 재전송은 하지 않으며, 실패한 선택 파일을 페이지 메모리에 보관해 사용자가 재시도할 수 있게 했습니다. 성공한 업로드의 응답으로 화면을 바로 갱신하여 후속 목록 요청 실패를 업로드 실패로 잘못 표시하지 않습니다.

## 브라우저 시나리오

1. 첨부 JSONL 실제 가져오기 → 완료 알림과 4281건 관측 확인.
2. 관리 중인 로컬 서버 일시 종료 → 서버 오프라인 안내, 모델 카드 연결 끊김, 재생 조작 비활성화 확인.
3. 작은 합성 검증 파일 선택 → 한국어 연결 오류와 `가져오기 다시 시도` 버튼 확인.
4. 서버 재실행 → 파일을 다시 선택하지 않고 재시도 성공. 검증 자료는 `시험_연결복구_확인.jsonl`로 명시.
5. 원래 비행으로 복귀, 29초 관측 표시, 두 모델 시험 응답과 판정 불일치 표시 확인.
6. LSTM 카드에서 근거 보기 → 28.224초 판정 시각으로 이동하고 기존 상세·차트 표시 확인.
7. 1280×800에서 핵심 3D·모델 영역 하단 674.29px, 재생 바 상단 707px: 겹침 없이 전체 표시. 1440×960에서도 확인.
8. 390px에서 데이터 진단·모니터링 메뉴 접근, 가로 넘침 없음, 실시간 연결 모달과 Escape 닫기 확인.
9. 새로고침 후 첨부 비행 선택 유지, 정상 상태의 uncaught 런타임 오류 없음 확인. 의도적 서버 중단 시 브라우저 네트워크 오류는 예상된 동작입니다.

화면 예시는 [dashboard-balanced-preview.jpg](dashboard-balanced-preview.jpg)에 저장했습니다. 화면의 AI 판정은 명확히 표시된 시험 응답이며 실제 모델 탐지 결과가 아닙니다. 확인 후 시험 모드를 해제하고 원래 비행과 실제 관측 화면을 남겼습니다.
